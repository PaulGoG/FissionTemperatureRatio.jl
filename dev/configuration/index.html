Configuration

A run is driven by one TOML file, config/<system>.toml, read by load_configuration against a data directory. The loader enforces what this page lists: the sections and keys it knows, the type of every key, its bounds or its enumerated choices, and the existence of every file named. An unknown section or key, a value outside its bounds, a choice it does not offer or a path that does not exist is refused with a message naming the key, so a run cannot start from a configuration it cannot honour. A key that is absent takes its default; a section marked required must be present even where every key of it has one. The shipped configurations set every key they read, so that the file states what the run honoured.

Every key that changes the result is a parameter of the run identifier, under the short key of the fifth column; Naming defines the identifier and metadata.toml records the parameters in full.

[system], required

The keys describe what was irradiated. The reaction code, the fissioning nucleus and the system label <symbol><A>_<channel> are derived from them, and the file is named by that label.

The $\nu(A)$ datasets of the system.

[multiplicity]
subdirectory = "Cf252_sf/nu_vs_A"
exclude = [
    { accession = "31845003", reason = "one usable fragment pair in range" },
]

An exclusion names its dataset by EXFOR accession. A label, Author year, takes the accession of each dataset as soon as a second one of the same author and year is retrieved, and an exclusion written against it would then match neither; the accession does not change. An exclusion that names no dataset of the directory is refused when the configuration is loaded. dataset = "<label>" remains for a tabulation that carries no accession; for a dataset that has one it is refused, with the accession to write.
